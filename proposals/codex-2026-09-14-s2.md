# DTS — Dense Technical Syntax

Apply these six to every passage. They cover the common case.

1. **Compression removes filler, never content.** Every fact the reader needs to act survives. When keeping a fact costs another sentence, write the sentence.
2. **Answer first.** No preamble, no question echo, no closing recap.
3. **One idea per sentence.** At most 15 words for a directive, 20 for description. Shorter is always better.
4. **Bullets and tables** for anything enumerable. Never a prose list. Stop a list when the next row adds nothing the reader will act on.
5. **Delete filler and hedge stacks.** State the fact, or state that it is unconfirmed.
6. **Reproduce technical spans verbatim.** Code, paths, commands, identifiers, and error strings stay character-exact.

Read [`references/grammar.md`](references/grammar.md) before rewriting a whole document. Run the audit in [`references/check.md`](references/check.md) before delivering one.

Brevity governs prose only. Code inside an edit stays complete, syntactically valid, and self-contained. Treat `// ... existing code` and stub placeholders as defects.

Never re-output unchanged code to confirm a change.

## 1. Re-critique of P33–P35

### P33 — staged autonomy, cross-family audit panel

Blinding and one reconciliation round do not establish independence. They only reduce direct answer copying.

Common causes still correlate panel members:

- Shared foundation models create common blind spots.
- Shared prompts create common framing errors.
- Shared `akar` sources propagate poisoned evidence.
- Shared tools return identical incomplete results.
- Evolution pressure makes families converge across seasons.
- Repeated reviewer pairings create reciprocal approval norms.
- Descendant families can form disguised voting blocs.

“Different family” is therefore an inadequate independence rule.

P33 needs these invariants:

- The harness assigns reviewers after artifacts become immutable.
- A reviewer cannot audit its ancestor, descendant, or recent reciprocal reviewer.
- Panel quorum counts distinct failure domains, not family labels alone.
- Each reviewer submits a sealed verdict before seeing other verdicts.
- The harness preserves every sealed verdict after reconciliation.
- Reconciliation creates a new record instead of replacing prior records.
- Missing and abstaining reviewers do not count toward quorum.
- Material dissent remains visible after the final decision.
- A deterministic rule resolves unresolved disagreement.
- Automatic stage demotion follows integrity or quality threshold breaches.
- Every stage transition records its evidence, approver, and policy snapshot.

Failure domains can include model provider, model lineage, prompt lineage, and evidence set. Perfect independence remains impossible. P33 must describe correlation reduction instead.

One reconciliation round has a specific purpose. It identifies factual misunderstandings and scope disagreements. It must not manufacture consensus.

The panel also needs capture resistance:

- Assignment rotation limits repeated reviewer pairs.
- Reciprocal-review limits prevent approval trading.
- Historical disagreement rates expose suspicious unanimity.
- Sampled operator audits estimate panel false-negative rates.
- Family cloning does not create another quorum vote.
- Panel membership changes remain separate from reviewed evolution changes.

Free autonomy needs automatic demotion. “Free” must mean bounded execution without routine approval. It cannot mean irreversible or unaudited execution.

### P34 — DAG mutation grammar between seasons

Restricting mutations between seasons creates a sound snapshot boundary. The grammar still needs transactional semantics.

Required invariants:

- Each season pins one immutable DAG revision.
- No running season observes a partial mutation.
- Each mutation names its base Git tree SHA.
- A stale base SHA rejects the mutation.
- The harness applies all operations atomically.
- Pre-application and post-application lint both pass.
- The resulting graph remains acyclic.
- Required roots and terminal nodes remain reachable.
- Deleted nodes receive tombstones for historical reports.
- Node identifiers remain stable across renames.
- Schema compatibility covers inputs, outputs, artifacts, and budgets.
- Every mutation records author, reviewers, citations, and rollback data.
- Concurrent proposals receive deterministic ordering or explicit rejection.
- Rollback creates another ledger event. It never erases the mutation.

P34 also needs a relationship with P12.

One semantic DAG mutation can require several mechanical operations. For example, node replacement needs edge removal, node insertion, and edge insertion. P12’s `primary_change` must identify the semantic change. Supporting operations belong to the same atomic patch.

The dashboard must never summarize that patch as only its primary operation. Hidden supporting operations can carry the actual risk.

Mutation deletion also needs policy. Removing a node can erase audit duties, evidence production, or safety checks. P34 needs protected node classes and minimum graph invariants.

### P35 — closed-wall registry

A permanent closed-wall registry will accumulate stale conclusions. It can become an institutionalized blind spot.

Primary failure modes:

- Incorrect closure suppresses future investigation.
- New evidence invalidates an old closure.
- Broad scope blocks adjacent valid work.
- Malicious agents close areas that threaten their lineage.
- Repeated prompt injection consumes growing context.
- Retrieval omits a relevant wall without exposing that omission.
- Full injection anchors every agent toward past conclusions.
- Registry maintenance becomes another recurring panel workload.

A wall needs structured scope:

- `wall_id`
- claim that remains closed
- explicit exclusions
- closure evidence
- evidence content hashes
- ratifying authority
- creation season
- review date
- applicability tags
- status
- superseded wall
- reopening proposals
- dissent

Use lifecycle states such as `closed`, `review_due`, `reopened`, and `superseded`. Never remove old wall records.

Reopening authority needs stage-specific rules:

- Manual stage: an agent proposes reopening. The operator decides.
- Panel stage: an unrelated panel ratifies evidence-backed reopening.
- Free stage: the panel can reopen within policy bounds.
- Harness: mechanical expiry changes `closed` into `review_due`.
- Harness: semantic evidence conflicts cannot trigger automatic reopening.

The harness cannot judge whether new evidence refutes a wall. It can detect changed or missing evidence hashes.

Do not inject the complete registry. Inject bounded wall summaries selected by deterministic scope rules. Record the selected wall IDs in each execution event.

A reasonable initial cap is eight summaries or 2 KiB per node. Keep the cap configurable. A node can query full wall records through the CLI.

P35 also needs closure authority. Closing a wall is more dangerous than reopening one. Closure suppresses future search. It needs stronger evidence and broader review.

## 2. Minimum operator visibility

SAT’s three levels map cleanly onto Rumpun. “Reasoning” must mean structured rationale. The UI must not depend on hidden chain-of-thought.

| Object | SAT 1: activity and cause | SAT 2: rationale and evidence | SAT 3: projection and uncertainty |
|---|---|---|---|
| Season | Objective, state, stage, pinned SHA, elapsed time | Stop cause, policy decisions, unresolved findings | Critical path, remaining budget, completion risks |
| DAG node | State, dependencies, actor, retries | Input selection, output claim, cited `akar` | Expected completion, blocked dependencies, likely downstream impact |
| `benih` | Owner, origin, lifecycle state | Selection or rejection rationale | Promotion chance, missing evidence, expiry risk |
| Artifact | Path, producer, content hash, creation event | Claim summary, checks run, citations | Expected consumers, compatibility risk |
| `akar` citation | Source locator, captured hash, access state | Agent-stated relevance and quoted claim boundary | Staleness, contradiction, coverage gaps |
| Evolution diff | Exact operations, base SHA, resulting SHA | `primary_change`, supporting operations, evidence | Blast radius, rollback path, expected outcome |
| Audit | Reviewer, eligibility, sealed verdict | Findings, disagreement, reconciliation changes | Residual risk and required follow-up |

The operator needs different emphasis at each autonomy stage.

| Stage | Minimum foreground view |
|---|---|
| Manual | Approval queue, exact diff, evidence, dissent, rollback, policy checks |
| Panel | Panel eligibility, sealed verdicts, quorum, reconciliation delta, exceptions |
| Free | Policy envelope, applied changes, integrity events, drift, sampled audits, rollback readiness |

Higher autonomy needs stronger provenance and exception reporting. It does not need more routine detail.

Every view needs drill-down. The default view stays compact:

1. What needs operator action?
2. Is the season progressing?
3. What changed?
4. What evidence supports the change?
5. What disagreement remains?
6. Can the operator stop or reverse it?

Implement three layers from one read model.

### Priority 0: machine-readable status

Create a stable internal snapshot and `--json` output first. Every presentation must consume this snapshot.

Without this layer, terminal and HTML views will disagree.

### Priority 1: `rumpun board`

`rumpun board` must work as a non-interactive terminal snapshot. Add `--watch` for a live TUI.

The default must remain useful through:

- SSH sessions
- narrow terminals
- redirected output
- monochrome terminals
- screen readers
- CI logs

Recommended panels:

- Action queue
- Season identity and pinned revisions
- DAG critical path
- Running, blocked, failed, and completed nodes
- Budget and time
- Recent harness events
- Audit disagreement
- Pending evolution
- Integrity warnings

A fullscreen interface must remain optional. The snapshot form is the durable CLI experience.

### Priority 2: static season report

Generate one self-contained HTML report after each season. This is the stronger between-season review surface.

The report needs:

- Embedded source snapshot hash
- Generation timestamp
- Season outcome
- Timeline
- DAG state history
- Artifact and citation index
- Audit panel record
- Evolution diff
- Closed-wall changes
- Alerts and resolutions
- Operator decisions
- Links to local ledger files

The report is derived output. It is never authoritative. Display `STALE` when current ledger hashes differ.

A deterministic report also produces reviewable Git diffs. Avoid remote assets and network-loaded scripts.

### Priority 3: local web server

Defer the server until board and report data models stabilize.

If implemented:

- Bind to `127.0.0.1` by default.
- Remain read-only.
- Expose no unique control action.
- Require CLI commands for approvals and mutations.
- Support SSH port forwarding.
- Reuse the same snapshot renderer.
- Avoid a persistent database.

The server adds lifecycle, security, and stale-state costs. Its main benefit is live graph navigation.

## 4. Trust surface

Use visible provenance labels in every view:

- `[H]`: harness-observed
- `[A]`: agent-authored
- `[D]`: derived from stated inputs

Color can supplement these labels. Color cannot replace them.

| Value | Class | Qualification |
|---|---|---|
| Process start and end | `[H]` | Capture with monotonic and wall clocks |
| Exit code and signal | `[H]` | Record directly from process supervision |
| Retry and termination | `[H]` | Include the policy rule |
| File content hash | `[H]` | Hash before and after execution |
| File mtime | `[H]` | Observed metadata, weak integrity evidence |
| Git tree and commit SHA | `[H]` | Content identity only |
| Git author and timestamp | `[A]` | Agents can forge both fields |
| DAG transition | `[H]` | The harness must own transitions |
| Wall injection set | `[H]` | Record exact IDs and registry revision |
| Citation target existence | `[H]` | Existence does not establish support |
| Citation relevance | `[A]` | Reviewer or agent judgment |
| Verdict | `[A]` | Preserve author and sealed version |
| Discovery | `[A]` | Treat as a claim until checked |
| Confidence | `[A]` | Track calibration across seasons |
| Test exit code | `[H]` | Only when the harness runs the test |
| Test interpretation | `[A]` | Keep separate from process result |
| Success status | `[D]` | Show the exact policy expression |
| Remaining-time forecast | `[D]` or `[A]` | Label historical and agent forecasts separately |

The harness event ledger must live outside agent-writable paths. Otherwise, `[H]` means “observed,” not tamper-resistant.

If agents share the harness Unix identity, local permissions provide no strong boundary. The threat model must state this limit. Strong integrity requires process separation and a harness-only append key.

P12’s evidence citations remain agent-authored claims. The harness can check locator resolution and content hashes. It cannot establish that the evidence supports the claim.

## 5. Alerting and stall semantics

An alert must represent a new actionable state. Everything else belongs in a digest.

### Immediate alerts

- Operator approval becomes required.
- A process crosses a forbidden policy boundary.
- The harness detects ledger or artifact tampering.
- Panel quorum becomes impossible.
- Material dissent remains unresolved.
- The DAG enters deadlock.
- Retry limits become exhausted.
- A protected invariant fails.
- Budget exhaustion stops required work.
- Free-stage evolution exceeds its allowed blast radius.
- Rollback becomes unavailable after a mutation.

### Digest events

- Season completion
- Ordinary node completion
- Expected retries
- Budget threshold warnings
- Wall review dates
- Non-blocking panel dissent
- Historical performance drift
- New `benih` awaiting later triage

### Quiet events

- Heartbeats
- Log lines
- File mtimes without content changes
- Expected dependency waiting
- Repeated updates to an open alert
- Successful routine checks

`stall_minutes` cannot rely on missing log output. Agents can emit meaningless output forever.

Define progress as a harness-observed durable transition:

- Node state changes
- New artifact content hash
- Accepted checkpoint
- Dependency completion
- Tool completion tied to the node
- Harness-recorded work unit completion

Exclude these signals:

- Heartbeats alone
- Repeated identical logs
- Mtime-only changes
- Agent-written “still working” records

Add distinct states:

- `waiting`: blocked by an unfinished dependency
- `idle`: no runnable assigned work
- `suspected_stall`: no durable progress within the threshold
- `stalled`: grace period expired
- `deadlocked`: unfinished graph has no runnable path

Alert once when the incident opens. Update the same incident. Alert again only after severity escalation. Record resolution without another urgent ping.

Local-first alert delivery needs one optional command hook. Disable it by default. Pass a bounded event document through stdin. Never interpolate agent text into a shell command.

## 1. Re-critique of P33–P35

### P33 — staged autonomy, cross-family audit panel

Blinding and one reconciliation round do not establish independence. They only reduce direct answer copying.

Common causes still correlate panel members:

- Shared foundation models create common blind spots.
- Shared prompts create common framing errors.
- Shared `akar` sources propagate poisoned evidence.
- Shared tools return identical incomplete results.
- Evolution pressure makes families converge across seasons.
- Repeated reviewer pairings create reciprocal approval norms.
- Descendant families can form disguised voting blocs.

“Different family” is therefore an inadequate independence rule.

P33 needs these invariants:

- The harness assigns reviewers after artifacts become immutable.
- A reviewer cannot audit its ancestor, descendant, or recent reciprocal reviewer.
- Panel quorum counts distinct failure domains, not family labels alone.
- Each reviewer submits a sealed verdict before seeing other verdicts.
- The harness preserves every sealed verdict after reconciliation.
- Reconciliation creates a new record instead of replacing prior records.
- Missing and abstaining reviewers do not count toward quorum.
- Material dissent remains visible after the final decision.
- A deterministic rule resolves unresolved disagreement.
- Automatic stage demotion follows integrity or quality threshold breaches.
- Every stage transition records its evidence, approver, and policy snapshot.

Failure domains can include model provider, model lineage, prompt lineage, and evidence set. Perfect independence remains impossible. P33 must describe correlation reduction instead.

One reconciliation round has a specific purpose. It identifies factual misunderstandings and scope disagreements. It must not manufacture consensus.

The panel also needs capture resistance:

- Assignment rotation limits repeated reviewer pairs.
- Reciprocal-review limits prevent approval trading.
- Historical disagreement rates expose suspicious unanimity.
- Sampled operator audits estimate panel false-negative rates.
- Family cloning does not create another quorum vote.
- Panel membership changes remain separate from reviewed evolution changes.

Free autonomy needs automatic demotion. “Free” must mean bounded execution without routine approval. It cannot mean irreversible or unaudited execution.

### P34 — DAG mutation grammar between seasons

Restricting mutations between seasons creates a sound snapshot boundary. The grammar still needs transactional semantics.

Required invariants:

- Each season pins one immutable DAG revision.
- No running season observes a partial mutation.
- Each mutation names its base Git tree SHA.
- A stale base SHA rejects the mutation.
- The harness applies all operations atomically.
- Pre-application and post-application lint both pass.
- The resulting graph remains acyclic.
- Required roots and terminal nodes remain reachable.
- Deleted nodes receive tombstones for historical reports.
- Node identifiers remain stable across renames.
- Schema compatibility covers inputs, outputs, artifacts, and budgets.
- Every mutation records author, reviewers, citations, and rollback data.
- Concurrent proposals receive deterministic ordering or explicit rejection.
- Rollback creates another ledger event. It never erases the mutation.

P34 also needs a relationship with P12.

One semantic DAG mutation can require several mechanical operations. For example, node replacement needs edge removal, node insertion, and edge insertion. P12’s `primary_change` must identify the semantic change. Supporting operations belong to the same atomic patch.

The dashboard must never summarize that patch as only its primary operation. Hidden supporting operations can carry the actual risk.

Mutation deletion also needs policy. Removing a node can erase audit duties, evidence production, or safety checks. P34 needs protected node classes and minimum graph invariants.

### P35 — closed-wall registry

A permanent closed-wall registry will accumulate stale conclusions. It can become an institutionalized blind spot.

Primary failure modes:

- Incorrect closure suppresses future investigation.
- New evidence invalidates an old closure.
- Broad scope blocks adjacent valid work.
- Malicious agents close areas that threaten their lineage.
- Repeated prompt injection consumes growing context.
- Retrieval omits a relevant wall without exposing that omission.
- Full injection anchors every agent toward past conclusions.
- Registry maintenance becomes another recurring panel workload.

A wall needs structured scope:

- `wall_id`
- claim that remains closed
- explicit exclusions
- closure evidence
- evidence content hashes
- ratifying authority
- creation season
- review date
- applicability tags
- status
- superseded wall
- reopening proposals
- dissent

Use lifecycle states such as `closed`, `review_due`, `reopened`, and `superseded`. Never remove old wall records.

Reopening authority needs stage-specific rules:

- Manual stage: an agent proposes reopening. The operator decides.
- Panel stage: an unrelated panel ratifies evidence-backed reopening.
- Free stage: the panel can reopen within policy bounds.
- Harness: mechanical expiry changes `closed` into `review_due`.
- Harness: semantic evidence conflicts cannot trigger automatic reopening.

The harness cannot judge whether new evidence refutes a wall. It can detect changed or missing evidence hashes.

Do not inject the complete registry. Inject bounded wall summaries selected by deterministic scope rules. Record the selected wall IDs in each execution event.

A reasonable initial cap is eight summaries or 2 KiB per node. Keep the cap configurable. A node can query full wall records through the CLI.

P35 also needs closure authority. Closing a wall is more dangerous than reopening one. Closure suppresses future search. It needs stronger evidence and broader review.

## 2. Minimum operator visibility

SAT’s three levels map cleanly onto Rumpun. “Reasoning” must mean structured rationale. The UI must not depend on hidden chain-of-thought.

| Object | SAT 1: activity and cause | SAT 2: rationale and evidence | SAT 3: projection and uncertainty |
|---|---|---|---|
| Season | Objective, state, stage, pinned SHA, elapsed time | Stop cause, policy decisions, unresolved findings | Critical path, remaining budget, completion risks |
| DAG node | State, dependencies, actor, retries | Input selection, output claim, cited `akar` | Expected completion, blocked dependencies, likely downstream impact |
| `benih` | Owner, origin, lifecycle state | Selection or rejection rationale | Promotion chance, missing evidence, expiry risk |
| Artifact | Path, producer, content hash, creation event | Claim summary, checks run, citations | Expected consumers, compatibility risk |
| `akar` citation | Source locator, captured hash, access state | Agent-stated relevance and quoted claim boundary | Staleness, contradiction, coverage gaps |
| Evolution diff | Exact operations, base SHA, resulting SHA | `primary_change`, supporting operations, evidence | Blast radius, rollback path, expected outcome |
| Audit | Reviewer, eligibility, sealed verdict | Findings, disagreement, reconciliation changes | Residual risk and required follow-up |

The operator needs different emphasis at each autonomy stage.

| Stage | Minimum foreground view |
|---|---|
| Manual | Approval queue, exact diff, evidence, dissent, rollback, policy checks |
| Panel | Panel eligibility, sealed verdicts, quorum, reconciliation delta, exceptions |
| Free | Policy envelope, applied changes, integrity events, drift, sampled audits, rollback readiness |

Higher autonomy needs stronger provenance and exception reporting. It does not need more routine detail.

Every view needs drill-down. The default view stays compact:

1. What needs operator action?
2. Is the season progressing?
3. What changed?
4. What evidence supports the change?
5. What disagreement remains?
6. Can the operator stop or reverse it?

| Value | Class | Qualification |
|---|---|---|
| Process start and end | `[H]` | Capture with monotonic and wall clocks |
| Exit code and signal | `[H]` | Record directly from process supervision |
| Retry and termination | `[H]` | Include the policy rule |
| File content hash | `[H]` | Hash before and after execution |
| File mtime | `[H]` | Observed metadata, weak integrity evidence |
| Git tree and commit SHA | `[H]` | Content identity only |
| Git author and timestamp | `[A]` | Agents can forge both fields |
| DAG transition | `[H]` | The harness must own transitions |
| Wall injection set | `[H]` | Record exact IDs and registry revision |
| Citation target existence | `[H]` | Existence does not establish support |
| Citation relevance | `[A]` | Reviewer or agent judgment |

P12’s evidence citations remain agent-authored claims. The harness can check locator resolution and content hashes. It cannot establish that the evidence supports the claim.

## 5. Alerting and stall semantics

An alert must represent a new actionable state. Everything else belongs in a digest.

### Immediate alerts

- Operator approval becomes required.
- A process crosses a forbidden policy boundary.
- The harness detects ledger or artifact tampering.
- Panel quorum becomes impossible.
- Material dissent remains unresolved.
- The DAG enters deadlock.
- Retry limits become exhausted.
- A protected invariant fails.
- Budget exhaustion stops required work.
- Free-stage evolution exceeds its allowed blast radius.
- Rollback becomes unavailable after a mutation.

### Digest events

- Season completion
- Ordinary node completion
- Expected retries
- Budget threshold warnings
- Wall review dates
- Non-blocking panel dissent
- Historical performance drift
- New `benih` awaiting later triage

### Quiet events

- Heartbeats
- Log lines
- File mtimes without content changes
- Expected dependency waiting
- Repeated updates to an open alert
- Successful routine checks

`stall_minutes` cannot rely on missing log output. Agents can emit meaningless output forever.

Define progress as a harness-observed durable transition:

- Node state changes
- New artifact content hash
- Accepted checkpoint
- Dependency completion
- Tool completion tied to the node
- Harness-recorded work unit completion

Exclude these signals:

- Heartbeats alone
- Repeated identical logs
- Mtime-only changes
- Agent-written “still working” records

Add distinct states:

- `waiting`: blocked by an unfinished dependency
- `idle`: no runnable assigned work
- `suspected_stall`: no durable progress within the threshold
- `stalled`: grace period expired
- `deadlocked`: unfinished graph has no runnable path

Alert once when the incident opens. Update the same incident. Alert again only after severity escalation. Record resolution without another urgent ping.

Local-first alert delivery needs one optional command hook. Disable it by default. Pass a bounded event document through stdin. Never interpolate agent text into a shell command.
